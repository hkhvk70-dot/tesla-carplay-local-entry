# 设置、停止和恢复

开始前请阅读 [踩坑记录与解决方法](PITFALLS.zh-CN.md)。其中包含热点立即踢人、DIRECT 无互联网、后台冻结、尺寸变化掉线、VPN 入口不可达和 APK 签名等实际问题的处理。

## 首次设置

1. Android 解锁并插入可用 SIM。打开移动数据，用手机浏览器确认外网可访问。
2. 开蓝牙和系统个人热点。设一个自己选择的热点名称和密码。最大连接设备数至少 3；iPhone、Tesla 和调试电脑都可能占用一个名额。把 WheelPlay 和本地入口的电池策略设为无限制，并允许应用正常后台运行。
3. 安装并准备 WheelPlay。按应用要求授予蓝牙、附近设备、网络/定位等权限；具体请求以系统授权页为准。不要为排查一般故障清除配对数据。
4. WheelPlay「设置 → 无线连接 → 连接网络」选择「设备热点」，输入与系统热点一致的名称和密码。不是 DIRECT 网络的凭据。
5. 关闭「设置 → 画面与音频 → 自适应浏览器尺寸」。当前使用固定画面参数，避免网页尺寸变化引发 CarPlay 会话重启。
6. 在 WheelPlay 发起 iPhone 连接，在 iPhone 同意 CarPlay。先确认 Android 接收端有画面。iPhone 和 Tesla 最终都加入这个系统热点。
7. 如果 Android 浏览器正在显示 CarPlay，退出这个网页，释放唯一浏览器控制会话。保持 WheelPlay 和热点运行。
8. 启动「CarPlay 本地入口」，点「启动本地入口」。首次需要手动同意系统 VPN 授权。不要同时运行另一款 VPN。
9. Tesla 加入 Android 热点，打开完整地址 `http://7.7.7.1:8080/`。按 WheelPlay 网页提示配对、启动显示。停车状态下点应用图标、拖动地图验证。

已有可工作的接收端可先使用，不要求为了安装入口而重装 WheelPlay。本仓库不提供 WheelPlay 的认证材料或现场自用 APK。

## 图像模式与音频

WheelPlay 上游提供 WebRTC 与 JPEG 选项。可以先用 JPEG 验证页面和触控，再测试 WebRTC；本次现场反馈没有记录具体模式，不能把 WebRTC、高帧率或某个视频编码写为已通过。

音频可另测 iPhone 蓝牙连接 Tesla 后的输出。CarPlay 连接可能影响 iOS 音频路由，需要分别检查音乐、导航提示、通话和 Siri。本次音频未验收。

## 停止与回滚

- 本地入口点击「停止并回滚」。入口会关闭两个接口描述符；7 地址停止可访问属预期。它不删除 WheelPlay 配对或系统热点配置。
- 需要停止接收端时，在 WheelPlay 断开；如其后台仍持有 Wi-Fi Direct 组，可通过 Android 应用信息强行停止，随后重新启动。不要把清除数据作为日常恢复步骤。
- 卸载本地入口前先停止它。调试 APK 与自行构建 APK 签名可能不同，不能跨签名覆盖安装。
- WheelPlay 网络补丁的撤销命令见补丁目录。恢复原代码后仍需自行构建相同签名的应用；这不是一键 APK 降级功能。

## 手机重启后的手动顺序

1. 解锁 Android；启用 SIM 移动数据、蓝牙与系统热点，检查最大连接数。
2. 打开 WheelPlay，确认设备热点模式/凭据仍正确，恢复 iPhone CarPlay。
3. 打开本地入口并启动；必要时确认 VPN 授权。
4. Tesla 重新加入热点，刷新网页；浏览器配对记录仍有效时直接启动显示。

这是推荐恢复顺序；**本次真实车机在普通热点模式下的完整重启恢复尚未验收**。应用没有开机自启。
